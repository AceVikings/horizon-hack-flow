## A. PolicyVault ABI (Lane A must match `policyVaultAbi`)

1. **Custom errors** (§4.1 only gives `TradeCap`, `ExitPrice`, `ConstructorCheck`, `Exposure`, `OracleInvalid`, `OracleStale`):
   reason 1 `VaultPaused()` (cannot be `Paused`: it collides with `event Paused`), 2 `NotAgent(address caller)`,
   3 `ZeroAmount()`, 4 `DeadlineExpired(uint256 deadline, uint256 timestamp)`, 5 `PairNotAllowed(address tokenIn)`,
   6 `OracleInvalid(int256 answer, uint256 updatedAt)` (zeros when `latestRoundData` reverted),
   7 `OracleStale(uint256 updatedAt, uint32 maxOracleAge)`,
   8 `OracleDeviation(uint256 spot, uint256 twap, uint256 oracle, uint16 maxOracleDeviationBps)` (`twap = 0` when `observe` reverted),
   9 `TradeCap(uint256 notionalUsd, uint256 cap)`, 10 `EpochCap(uint256 spentUsd, uint256 notionalUsd, uint256 cap)`,
   11 `Cooldown(uint256 lastTradeAt, uint32 cooldown)`, 12 `Slippage(uint256 minAmountOut, uint256 minOutFloor)`,
   13 `InsufficientBalance(address token, uint256 balance, uint256 amountIn)`,
   14 `Exposure(uint256 exposureUsd, uint256 addedUsd, uint256 maxExposureUsd)` (step 13: added = grossed notional; step 16: added = 0, exposure = post-swap),
   15 `ExitPrice(uint256 twap, uint256 oracle, uint16 maxExitDiscountBps)`.
   Non-reason: `ConstructorCheck(uint8)` (codes in `CONSTRUCTOR_CHECK`), `NotOwner(address)`, `NotPendingOwner(address)`,
   `NotPauser(address)`, `InvalidLimits(uint8 field)` (1-based Limits field, `LIMITS_FIELD`), `ZeroAddress()`,
   `PostCondition(uint8)` (`POST_CONDITION`: 1 tokenIn overspent, 2 tokenOut < min, 3 allowance ≠ 0). OZ v5 `ReentrancyGuardReentrantCall`, `SafeERC20FailedOperation` listed for decoding.
2. **Added views** (additive): `lastTradeAt() → uint256` (state named in §4.2 step 10; daemon needs it for `cooldownRemainingSec`) and `pendingOwner() → address` (two-step ownership).
3. **Constructor is not frozen** (spec gives no signature; Lane A owns deploy args). It must still run the §4.1 asserts with the `ConstructorCheck` codes above.
4. **`check()` outputs on failure:** `oraclePrice` set from step 6; `notionalUsd`, `minOutFloor`, `exitPath` computed immediately after step 7 (before steps 8–13); fields not computable at the failing step are 0. The TS mirror `checkMirror` implements exactly this; the parity suite should assert it.
5. `answeredInRound` clause: not modelled in `checkMirror` (decided at deploy, §4.2 step 6).
6. Limits bounds enforced by `setLimits`: `epochDuration > 0`, `maxSlippageBps ≤ 1000`, `maxOracleDeviationBps ≤ 1000`, `maxOracleDeviationBps ≤ maxExitDiscountBps ≤ 2000`, `300 ≤ maxOracleAge ≤ 172800` (`validateLimits`). `maxTradeUsd = 0` is valid (disallow).

## E. Errors / envelope

1. Added codes: `ATE_INTERNAL` (§20 InternalError over MCP) and `ATE_CONFIG_INVALID` (§20 ConfigError). `ATE_PAYMENT_*` expanded to the eight §9.6 codes.
2. `ToolError.details?: Record<string, unknown>` (additive): for `ATE_APPROVAL_REQUIRED` it is `StrategyApprovalPending { changeId, diff, renderedDiff, expiresAt }` — the spec needs a `changeId` for `/strategy/approve` but the envelope had nowhere to put it.
3. Schema-invalid tool arguments are a JSON-RPC `InvalidParams` error (no `ATE_*` code exists for them), not a `ToolResult`.
4. Agent scope patching a non-tunable `ate_strategy_set` field → `ATE_TOOL_NOT_ALLOWED` (spec only says "may change only").
5. "maybe"/"varies" retryability: `ATE_VENUE_ERROR` defaults `true` (callers override per cause); payment codes per `ERROR_RETRYABLE`.

## T. Types / wire units

1. All amounts are decimal strings (§12). Suffix convention: `*Usd` = human USD decimal ("25"), `*UsdE8` = 8-dp vault integer, prices = 8-dp integer strings, token amounts = smallest units. `Limits`/`SwapParams`/`CheckResult` use bigint (viem decoding: uint16/32 → number).
2. Tool output (`data`) shapes are not in the spec; they are frozen in `packages/core/src/tools.ts` (`ToolIO`, `ToolOutput<'ate_…'>`).
3. Tool inputs not given in §7.4 were authored: `ate_market_get`/`ate_positions`/`ate_strategy_get` `{ market? }`; `ate_journal_read { limit?, market?, kind?[], since?, before?, id? }`; `ate_decide`, `ate_pause`, `ate_signal_buy` per the §7.4 prose. The five §7.4 schemas are verbatim (a test parses them out of SPEC.md).
4. `Suppressed.side` widened to `Side` and `cause` adds `entry_interval` (v0.9 rule 7).
5. `Candidate` gains optional `createdAt`, `profile`, `guardReason`.

## J. Journal

1. Id prefixes beyond `prop_`/`dec_`: `exec_`, `att_`, `strat_`, `pause_`, `out_`, `pay_`, `payu_` (`DECISION_ID_PREFIX`).
2. `Decision.market?` added (a `no_trade` has no `intent`, so `ate_journal_read { market }` needs it).
3. `001_init.sql` = §12 verbatim + `schema_version(version, name, applied_at)`; the runner (`@ate/journal` `migrate`) inserts the row and sets WAL + `foreign_keys=ON`.

## S. Strategy seam

1. `Reservations.reserve(proposalId, claim)` takes a `ReservationClaim` (spec signature has only the id; the amount must come from somewhere). `release(proposalId, cause?)`: `executed` converts to used turnover, others free it.
2. `Invalidation` adds `onBreaker()` and `isInvalidated()`; `onGuardExit(market, reason)` returns invalidated ids.
3. `CandidateGenerator.generate` is synchronous: every chain/CEX read (incl. QuoterV2 impact samples, exit mark, the `check()` pre-filter) is pre-computed into `MarketSnapshot`. Suppressions come from the additive `CandidateEngine.run()`.
4. Additive `StrategyPatcher` interface for `ate_strategy_set` clamping/loosening; `LOOSENING_DIRECTION` and `RISK_PROFILES` mirror the v0.9 §11.5 table.

## C. Config / CLI / MCP

1. `strategy.portfolio.candidateTtlSec` accepts an int ≥ 120 or the literal `"from deployments/177.json"` (as written in §16).
2. v0.9 additive keys are optional: `scanSeconds`, per-market `minEntryIntervalSec`, `approvalFallback: "armed"`.
3. Config requires both markets' strategy blocks; `vaults` may hold 1–2 entries (each must have a venue market).
4. CLI: lanes add one file per command in `src/commands/<lane>/` exporting `default: CommandModule`; names reserved per §3.3 (`b/` includes `smoke`). The `rogue` token scope (v0.9) is in `TokenScope` only; no MCP tools for it.
5. MCP stub: `scope` from `ATE_STUB_SCOPE` (agent|chat), `ATE_STUB_HSP=1` registers `ate_signal_buy`. Results are JSON text content; `isError` mirrors `ok:false`.

## L. Lane E additions (additive only)

1. **New packages:** `@ate/approve` (`apps/approve/`: Swift `ate-approve` + TS payload codec/verifier/client, and the daemon
   approval service under `@ate/approve/daemon`), `@ate/payments` (`packages/payments/`), `@ate/worker` (`apps/worker/`).
2. **`@ate/journal` (additive):** dependency `viem`, subpath export `@ate/journal/attest` (tsup entry `src/attest/index.ts`),
   script `attest:register-schema`. Lane B's journal code is untouched.
3. **Approval payload wire format (frozen by Lane E):** `base64url(canonicalJson({ v:1, kind, aud, nonce, issuedAt, expiresAt, body }))`,
   kinds `payment|trade|chat_session|ui_attach|strategy|config`; the Secure Enclave signs the decoded bytes (ECDSA P-256/SHA-256,
   DER, base64 in the `approval` field). Verifiers rebuild the payload with the shared builders
   (`uiAttachPayload`, `chatSessionPayload`, `strategyPayload(StrategyApprovalPending)`, `paymentPayload`); `issuedAt = expiresAt − 60`.
   Pinned key: `~/.ate/approve-pubkey.json` `{ publicKey: <65-byte SEC1 hex>, keyId }`. An `approval` matching `^\d{8}$` is a TTY code.
4. **Lane B mount points:**
   - Approval endpoints: add `"@ate/approve": "workspace:*"` to `apps/daemon/package.json`; `createDaemonApproval(...)` from
     `apps/daemon/src/approval/index.ts` returns `{ routes, nodeHandler, tty, service }`. Routes: `POST /ui/attach`
     (step 1 `{}` unauthenticated, 5/min; step 2 needs a bearer — agent token from runtime.json — plus the signature),
     `POST /chat/session` (agent|ui), `POST /strategy/approve` (ui|session). Wire daemon stdin lines →
     `approval.tty.handleTtyLine(line)` (`approval-fallback enable|disable|status`; no HTTP route). When `ate_strategy_set`
     returns `ATE_APPROVAL_REQUIRED`, also call `approval.service.onStrategyPending(details)`.
     Callbacks Lane B supplies: `mintUiToken`, `mintSessionToken(sessionId)`, `getPendingStrategyChange(changeId)`,
     `applyStrategyChange(changeId, { method })`, `journalApproval({ purpose, method: "secure-enclave"|"tty", ref })`.
   - EAS attester: `import { Attester, buildAttestTx } from "@ate/journal/attest"`. After each `TradeExecuted` receipt:
     `attester.plan({ proposalId: <full hash>, rationaleHash, txHash, notionalUsdE8, exitPath, engine, origin, vault }, propDecisionId, agentBalanceWei)`
     → `enqueue` (`tx = { to, data, value: 0n, priority: "attest", gasHint }` for the TxQueue, lowest priority) | `defer` (below
     `attestFloorHsk`) | `give_up`. Report `onSubmitted(proposalId, txHash)`, then `onMined(receipt, bal)` → `{ record }`
     (an `attestation` journal input with `easUid`) or `{ retry }`; `onFailed(...)`; `failureRecord(id, "deferred"|"failed")`;
     `drainDeferred(bal)` after top-up; `deferredCount()` for `/status`. The module never signs or sends.
   - Schema UID (deterministic, no resolver, non-revocable): `0x1c0c01e337924a140372f0043e9a9a3125e0e276b6dae78382676b3d0e53a04f`
     — pin in `deployments/177.json`; ops registers with the `cast send` printed by `pnpm --filter @ate/journal attest:register-schema`.
5. **ate-pay HTTP API** (worker, via SSM forward, `Bearer <worker token>`): `GET /offers`, `POST /buy { offerId, context? }`,
   `GET /payments[/:id]` (includes `approvalRequest { stage, payload (base64url), prompt, expiresAt }` for `ate-approve sign`),
   `POST /payments/:id/approve { stage, approval }`, `POST /payments/:id/deny { stage }`, `GET /payments/:id/signal`.
