## A. PolicyVault ABI (Lane A must match `policyVaultAbi`)

1. **Custom errors** (§4.1 only gives `TradeCap`, `ExitPrice`, `ConstructorCheck`, `Exposure`, `OracleInvalid`, `OracleStale`):
   reason 1 `VaultPaused()` (cannot be `Paused`: it collides with `event Paused`), 2 `NotAgent(address caller)`,
   3 `ZeroAmount()`, 4 `DeadlineExpired(uint256 deadline, uint256 timestamp)`, 5 `PairNotAllowed(address tokenIn)`,
   6 `OracleInvalid(int256 answer, uint256 updatedAt)` (zeros when `latestRoundData` reverted),
   7 `OracleStale(uint256 updatedAt, uint32 maxOracleAge)`,
   8 `OracleDeviation(uint256 spot, uint256 twap, uint256 oracle, uint16 maxOracleDeviationBps)` (`twap = 0` when `observe` reverted),
   9 `TradeCap(uint256 notionalUsd, uint256 cap)`, 10 `EpochCap(uint256 spentUsd, uint256 notionalUsd, uint256 cap)`,
   11 `Cooldown(uint256 lastTradeAt, uint32 cooldown)`, 12 `Slippage(uint256 minAmountOut, uint256 minOutFloor)`,
   13 `InsufficientBalance(address token, uint256 balance, uint256 amountIn)`,
   14 `Exposure(uint256 exposureUsd, uint256 addedUsd, uint256 maxExposureUsd)` (step 13: added = grossed notional; step 16: added = 0, exposure = post-swap),
   15 `ExitPrice(uint256 twap, uint256 oracle, uint16 maxExitDiscountBps)`.
   Non-reason: `ConstructorCheck(uint8)` (codes in `CONSTRUCTOR_CHECK`), `NotOwner(address)`, `NotPendingOwner(address)`,
   `NotPauser(address)`, `InvalidLimits(uint8 field)` (1-based Limits field, `LIMITS_FIELD`), `ZeroAddress()`,
   `PostCondition(uint8)` (`POST_CONDITION`: 1 tokenIn overspent, 2 tokenOut < min, 3 allowance ≠ 0). OZ v5 `ReentrancyGuardReentrantCall`, `SafeERC20FailedOperation` listed for decoding.
2. **Added views** (additive): `lastTradeAt() → uint256` (state named in §4.2 step 10; daemon needs it for `cooldownRemainingSec`) and `pendingOwner() → address` (two-step ownership).
3. **Constructor is not frozen** (spec gives no signature; Lane A owns deploy args). It must still run the §4.1 asserts with the `ConstructorCheck` codes above.
4. **`check()` outputs on failure:** `oraclePrice` set from step 6; `notionalUsd`, `minOutFloor`, `exitPath` computed immediately after step 7 (before steps 8–13); fields not computable at the failing step are 0. The TS mirror `checkMirror` implements exactly this; the parity suite should assert it.
5. `answeredInRound` clause: not modelled in `checkMirror` (decided at deploy, §4.2 step 6).
6. Limits bounds enforced by `setLimits`: `epochDuration > 0`, `maxSlippageBps ≤ 1000`, `maxOracleDeviationBps ≤ 1000`, `maxOracleDeviationBps ≤ maxExitDiscountBps ≤ 2000`, `300 ≤ maxOracleAge ≤ 172800` (`validateLimits`). `maxTradeUsd = 0` is valid (disallow).

## E. Errors / envelope

1. Added codes: `ATE_INTERNAL` (§20 InternalError over MCP) and `ATE_CONFIG_INVALID` (§20 ConfigError). `ATE_PAYMENT_*` expanded to the eight §9.6 codes.
2. `ToolError.details?: Record<string, unknown>` (additive): for `ATE_APPROVAL_REQUIRED` it is `StrategyApprovalPending { changeId, diff, renderedDiff, expiresAt }` — the spec needs a `changeId` for `/strategy/approve` but the envelope had nowhere to put it.
3. Schema-invalid tool arguments are a JSON-RPC `InvalidParams` error (no `ATE_*` code exists for them), not a `ToolResult`.
4. Agent scope patching a non-tunable `ate_strategy_set` field → `ATE_TOOL_NOT_ALLOWED` (spec only says "may change only").
5. "maybe"/"varies" retryability: `ATE_VENUE_ERROR` defaults `true` (callers override per cause); payment codes per `ERROR_RETRYABLE`.

## T. Types / wire units

1. All amounts are decimal strings (§12). Suffix convention: `*Usd` = human USD decimal ("25"), `*UsdE8` = 8-dp vault integer, prices = 8-dp integer strings, token amounts = smallest units. `Limits`/`SwapParams`/`CheckResult` use bigint (viem decoding: uint16/32 → number).
2. Tool output (`data`) shapes are not in the spec; they are frozen in `packages/core/src/tools.ts` (`ToolIO`, `ToolOutput<'ate_…'>`).
3. Tool inputs not given in §7.4 were authored: `ate_market_get`/`ate_positions`/`ate_strategy_get` `{ market? }`; `ate_journal_read { limit?, market?, kind?[], since?, before?, id? }`; `ate_decide`, `ate_pause`, `ate_signal_buy` per the §7.4 prose. The five §7.4 schemas are verbatim (a test parses them out of SPEC.md).
4. `Suppressed.side` widened to `Side` and `cause` adds `entry_interval` (v0.9 rule 7).
5. `Candidate` gains optional `createdAt`, `profile`, `guardReason`.

## Lane C — strategy, trader, replay (additive)

1. **New packages:** `@ate/strategy` (`packages/strategy/`, subpath `@ate/strategy/replay`) and `@ate/trader` (`agents/trader/`,
   ships `PROMPT.md`). `apps/cli/package.json` gains `@ate/strategy`, `@ate/trader`, `@ate/daemon` (the `daemon`/`mcp` commands
   import `@ate/daemon` lazily so other commands never load it). Nothing frozen was changed.
2. **Seam factories** (match Lane B's `loadStrategy`): `createCandidateEngine(opts?)`, `createStrategyGuard(opts?)`,
   `createReservations()`, `createInvalidation(openProposals, reservations)`, plus `createStrategyPatcher()`.
   `createStrategyGuard()` without options consults the most recently created Invalidation (`currentInvalidation()`), so the
   daemon gets execute-time `ATE_STRATEGY_BLOCKED` (rule `invalidated`) without extra wiring. **Lane B:** add
   `"@ate/strategy": "workspace:*"` to `apps/daemon/package.json`, otherwise the dynamic `import("@ate/strategy")` falls back to the stub.
   Extra (non-frozen) helpers: `runEngine()` (adds per-market `notes` for silent entry blocks), `entryGate`, `evaluateStop`,
   `stepBreaker` (rule 6 state machine: actions `invalidate_buys|flatten|pause_all|notify|journal_unflattened`), `scoreVeto` (E13),
   ledger (`applyFill`/`pnl`, avg cost + FIFO lots), `decideRules`, `newlyOpenedEntryMarkets` (§11.1 scan trigger), `renderDiff`.
3. **Guard decisions where the spec is silent:**
   - Rule 7 "one entry per cycleSeconds" allows 10 s slack (`CYCLE_SLACK_SEC`) and treats another open entry proposal on the same
     market as a frequency block; both cycle and `minEntryIntervalSec` suppressions use `cause=entry_interval`, `bps` = net edge.
   - Rule 3b for sells: exposure after = exposure − notional (a sell can only help); guard exits exempt (turnover, exit reserve, edge gate).
   - Turnover-exempt (rule 3): guard exits, `discretionary_exit`, spread-revert `leg=close`, rebalance sells with target 0 / de-selected.
     Every other trade (incl. discretionary of either side and `smoke`) is an entry. The per-market allocation is recomputed from
     strategy + vault limits (`turnoverAllocationE8`); `MarketBook.turnover.allocationUsd` is informational.
   - Rule 1 expiry is checked at propose only (proposals carry their own 120 s TTL to execute); single-use = `consumedBy` null or self.
   - Entry gating also withholds entries (silently, in `notes`) while a guard exit is live on that market, the breaker is not armed,
     or the market is read-only. Dust: positions < $0.50 get no exit candidates; entries < $1 are not emitted.
   - Supra gate threshold defaults to 250 bps (`EngineOptions.supraMaxDisagreeBps` to pass `supra.maxDisagreeBps`).
4. **Patcher:** agent scope patching a non-tunable field throws `AteError(ATE_TOOL_NOT_ALLOWED)`; `maxDailyTurnoverUsd` is clamped to
   Σ vault (maxEpochUsd − maxExposureUsd), `maxPortfolioExposureUsd` to Σ maxExposureUsd, `maxPositionUsd`/`tradeSizeUsd` to the
   vault's caps; market fields without `patch.market` apply to every enabled target market; `needsMarketScope(patch)` flags
   stop-loss/TP changes without a market (chat must ask "HSK, BTC or both?").
5. **Runner ↔ daemon:** the runner talks to the daemon only through `ate mcp serve` (agent scope). Timeout records are
   `ate_decide { reason: "timeout" }` and rules-engine decisions carry a `[engine=rules]` rationale prefix — **Lane B:** please label
   decisions from the agent token with that prefix `engine=rules` (the MCP schema has no engine field). The runner's measured
   `candidateTtlSec` is written (only with `ate agent run --dry-run --record-ttl`) as top-level `candidateTtlSec` and
   `trader.{candidateTtlSec,p95LatencyMs,measuredCycles,measuredAt}` in `deployments/177.json`.

## CLOUD. Owner service, signer roles, cloud mode (lane CLOUD, additive)

1. **Signer roles** (`@ate/wallet`): `agent` reads only `ATE_AGENT_*`, `owner` only `ATE_OWNER_*`. Backends:
   keystore (keychain/file, passphrase), `secret` (`ATE_<ROLE>_KEY_ENC` = sealed blob JSON or base64, `ATE_<ROLE>_KEY_SECRET`),
   `kms` (`ATE_<ROLE>_KMS_KEY_ID`, `ATE_<ROLE>_KMS_REGION`; ECC_SECG_P256K1). Select with `ATE_<ROLE>_SIGNER`. The blob's
   role is bound into the AES-GCM AAD (`ate/<chain>/<role>/<id>`), so an owner blob never opens as agent. The daemon
   **refuses to start** when any `ATE_OWNER_*` is in its environment (`assertNoOwnerCredentials`).
2. **Owner service** (`apps/owner`, bin `flow-owner serve`): its own process, the only holder of the owner signer.
   Loopback HTTP, bearer token given by its supervisor on stdin (`FLOW_OWNER_STDIN=1`, line `{ "token" }`), never to the
   daemon. Prints `{ type: "owner.ready", port, owner, backend }` on stdout. Browser origins are rejected.
   - `GET /owner/state` → `{ chainId, owner, gasHsk, vaults: [{ market, address, owner, agent, guardian, paused, limits
     (decimal strings, USD caps × 1e8), ownedByUs }], latestDeploy, approvals: { touchId, passkeys }, defaults }`.
   - `POST /owner/op { op, … }` with op ∈ `deploy { markets?: ["hsk","btc"], agent, guardian?, limits?, seed? }` ·
     `setLimits { vaults?: "all"|addr[], limits }` (field names `maxTradeUsd` or `maxTradeUsdE8`, …) · `setAgent { agent,
     vaults? }` · `setGuardian { guardian, vaults? }` · `pause { vaults? }` · `unpause { vaults? }` · `withdraw { vault,
     token, amount, to? }` · `fundAgent { agent, wei }` · `seed { vaults? }` (testnet: mint test tokens into the vaults).
     → 200 `{ done: true, op, approvedBy: null|"touch-id"|"passkey", txs: [{ label, hash }], result? }` (deploy:
     `result.vaults [{ market, address, adapter }]`), or **428** `{ needsApproval: true, nonce, expiresAt, payload
     (base64url config payload, ate-approve signs it), challenge (base64url sha256(payload bytes), the WebAuthn
     challenge), prompt, changes }`. Step 2: `POST /owner/op { nonce, approval: { signature } | { webauthn } }`.
   - **The owner service decides** what needs approval, by reading the chain: looser limits (any field in the
     risk-raising direction), unpause, setAgent/setGuardian, withdraw, fundAgent, and deploy with limits looser than
     §19 defaults. Tighter limits, pause, seed and a default deploy run at once. It verifies the approval itself
     (Touch ID signature against the pinned key, or a passkey assertion against `<ownerHome>/passkeys.json`), so its
     supervisor cannot approve for the user. Approvals are single-use, 120 s.
   - `POST /owner/passkeys { id, publicKey (base64url COSE), counter, transports }`: the first passkey registers
     freely; later ones need an approval (same 428 flow).
3. **Renderer contract — D2's `window.ate.owner` shape is adopted as is** (`OwnerBridge` in `shared/setup-bridge.ts`):
   `status()`, `createVaults({ markets? })`, `setAgent(agent)`, `setLimits(limits, { markets?, loosening? })`,
   `unpause(market?)`. The bridge (Electron main / the cloud web bridge) runs step 1, and on 428 runs the approval
   ceremony itself (Touch ID via ate-approve on the desktop, a passkey in the browser), then step 2. `loosening` is
   advisory: the owner service classifies. `createVaults` deploys with the daemon's agent address and default limits,
   seeds on testnet, then calls the daemon's `POST /setup/vaults { source: "deploy", vaults }` and restarts it.
   Errors are `Res` errors; a cancelled approval is `ATE_APPROVAL_REQUIRED`. **Cloud:** `setup.confirmRisk` returns
   `{ method: "passkey" }` without prompting (the passkey prompt comes from the owner call, bound to the exact change).
4. **Cloud mode** (`apps/cloud`): one container, three processes. The gateway (public port, TLS by the host) supervises
   the owner service (gets `ATE_OWNER_*`) and the daemon (`ATE_OWNER_*` stripped, gets `ATE_AGENT_*`), serves the
   renderer with a web bridge (`window.ate` over HTTPS + WebSocket), and owns auth (passkey first, password fallback,
   httpOnly Secure SameSite=Strict session cookie, CSRF header, rate limits). `GET /healthz` is the health check.
